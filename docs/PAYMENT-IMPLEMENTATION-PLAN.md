# Payment and entitlement implementation plan

No live payments are enabled. Proposed price comes from validated server config (`premiumConfig`, default 499 USD cents); clients cannot set payment amount. Test mode uses no external service and no real money.

1. **Recommendation validation first.** Human-label repository-specific diagnoses, exact evidence and verification steps. Preserve free basic fixes and every free point-gain calculation. Do not sell generic/unsupported advice.
2. **Report access capability.** At scan time, issue an unguessable owner capability (server stores hash). A report ID alone is not authorization to read private detailed diagnoses. Never expose this capability in public share URLs. Bind every quote to server-stored repository ID, commit, analyzer/rule versions, profile and capability hash; never accept a client-supplied score/report body.
3. **Provider sandbox adapter.** Select a hosted checkout provider after review. Use server-created integer prices, USD currency and quote IDs, never client price metadata. Test receipt HMAC in this repository is not a provider integration. Implement the selected provider's official webhook verification and raw-body protocol separately; no card data enters this Worker.
4. **Durable transactional state.** Extend the existing coordinator storage with orders/events/entitlements only when needed. Atomically authenticate, validate quote/amount/currency/report and consume each provider event once. Bind provider event IDs to a unique order. Handle pending/paid/refunded/disputed events monotonically; refunds/disputes must not be reactivated by late/replayed payment events. The current store interface is not a production durable implementation.
5. **Capabilities and retention.** Premium lookup checks owner capability, exact report version and active entitlement; a guessed report ID or another purchase cannot authorize access. Decide delivery retention before checkout so a 24-hour free cache does not destroy a paid report. Retain only required redacted report/diagnosis data; define cancellation, deletion, refund and provider metadata handling. Never persist raw full repository source by default.
6. **Authorization testing.** Keep scoring and payment tests separate. Cover forged/tampered/stale/oversized webhooks; duplicate/concurrent/reordered events; currency/price/quote substitutions; cross-report and cross-capability reads; revoked/refunded access; provider failures/timeouts and data expiry. Compare identical report scoring before/after every payment status.
7. **Owner approval and launch.** Confirm readiness, sandbox integration, end-to-end verification and operational/refund runbooks, then obtain explicit owner approval before adding live provider credentials or enabling live checkout. Production hosting approval does not authorize live billing. Release initially disabled, with an emergency checkout switch. No paid cloud plan is enabled by these changes.

## Test-only module contract

`createTestQuote` requires explicit test mode, a versioned server report identity and a capability hash. `authorizeTestReceipt` requires a matching signed test receipt and calls an injected store. The store must implement idempotent transactional event consumption and terminal revocation semantics before production use. `mayReadPremium` checks active report/capability scope. `requestLiveCheckout` always refuses. There are no payment HTTP endpoints in the application.
